# 旧课程状态迁移

`course-state.json` 是课程主线、学习概况、复习队列和续学定位的唯一机器状态。`course-state.md` 可以作为便于阅读的备份，但生成器不会解析它，因此不能只靠 Markdown 计算进度。

## 何时迁移

出现以下任一情况时，先迁移再生成站点：

- 课程只有 `course-state.md`、进度表或旧版笔记；
- 已有 `course-state.json`，但没有非空 `steps` 数组；
- 状态字段仍使用 `✅`、`🟡`、`🔴`、`⏭` 等展示符号；
- 步骤编号或页面文件无法与 `course.json` 对上。

## 迁移步骤

1. 读取现有进度表、主笔记、课程清单和已有步骤页，确认真实步骤数与页面文件。
2. 在课程源目录创建或更新 `course-state.json`，使用 [html-course-spec.md](html-course-spec.md#机器状态) 中的最小结构。
3. 每个正式步骤写入一个 `steps` 项；尚未建立的步骤保留 `file: ""`，不要虚构不存在的页面。
4. 把展示状态映射为机器状态：
   - `✅ 掌握` → `mastered`
   - `🟡 半掌握` → `half`
   - `🔴 未掌握` → `failed`
   - `⏭ 跳过` → `skipped`
   - 未学习或没有记录 → `unlearned`
5. 用 `completed_steps` 记录真正完成且无阻塞的步骤；`half`、`failed`、`skipped` 不算完成。
6. 保留验收记录、复习队列和薄弱点；没有可靠记录的字段使用空数组，不要补造学习结果。
7. 运行生成器。若编号、页面文件或状态校验失败，回到原始课程资料核对，不要通过删除步骤规避错误。

## 无法判断时

以下信息缺失且无法从课程资料或用户回答中确认时，应暂停迁移并询问：

- 当前学到第几步；
- 步骤与页面文件的对应关系；
- 未通过、跳过或仅半掌握的状态；
- 待复习项是否已经连续答对两次。

迁移完成后，在 `course-state.md` 保留一份面向人的摘要即可；后续续学仍以 JSON 为准。
