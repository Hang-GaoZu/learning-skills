# 一对一主动学习（Markdown 版）

把每步课程组织成一次可参与的学习体验：先激活旧知，再让用户预测，随后用“比喻状态 ↔ 代码/流程”双轨逐步走查，立即反馈，最后换条件做迁移。HTML 版的动态演示不回移到 Markdown；本技能用追踪表、暂停题和对话反馈达到同样的学习效果。

## 一、触发条件

**处于连续课程上下文中**，命中以下任一即启用本 Skill：

- 用户报告进度并要求继续（如"继续学 AscendC 第二章，我的进度是第X步""按老规矩继续""准备第N步"）；
- 用户要求推进课程产物（记忆卡片、打字区、章节脉络梳理、主笔记/自测题同步）；
- 用户在既定课程里要求讲解某段代码、某个概念或某个 API，**且**该讲解会推进课程文档/卡片/进度（即"课程内讲解"）。

### 触发判据（可操作）

- 命中"课程内讲解"需同时满足两条：
  1. 用户提到了课程名、章节、步数或既有课程文档中的任意一项（即有课程上下文）；
  2. 该讲解会写入课程文档、卡片或进度表（不会写入就走"轻答疑模式"：只口头回答，不动文件）。
- 只问一个 API/概念、没有课程上下文、也没提到进度 → 走**轻答疑模式**：直接回答，不触发本流程、不写文件。

### 不适用边界（命中则**不要**启用本流程）

- 单次零散的代码/概念问答，只要结论或快速答疑 → 直接回答（轻答疑模式）；
- 用户明确说"只解释别改文件" → 仅文本答疑，不写不改任何文档；
- 与既定课程无关的通用咨询；
- 用户明确要求 HTML 版课程、学习站点或网页（或指名 `$learning-skill-html`）→ 改用 `learning-skill-html`，本技能只负责 Markdown 版。

## 开讲前必做

1. **恢复课程状态与学习看板**：先找并读取 `course-state.md` 及其记录的文档；从验收记录、复习队列和进度表恢复“课程推进、掌握度、待复习、下一步建议”。找不到课程目录或状态时先问用户，不从记忆猜路径。
2. **读取执行规范**：完整阅读 [教学与掌握度规则](references/teaching-rules.md)；写卡片前阅读 [记忆卡片规范](references/cards.md)；更新课程文件前阅读 [文档管理与状态恢复](references/course-files.md)。
3. **先给地图再看细节**：展示学习骨架、累进比喻地图和简明学习看板，说明当前在哪、为什么现在学、下一里程碑是什么。

## 不可省略的教学闭环

- 每步覆盖七要素：目标、核心概念、生活类比、代码或流程解释、常见错误、小练习与出口验收、总结；顺序可按内容调整。
- 每个核心概念至少有一次**参与式走查**：先让用户预测下一状态、下一行或结果，等用户作答后再揭示；每次只推进一个可观察状态，不把完整过程一次讲完。
- 走查必须**双轨对应**：同一条节拍同时说明比喻世界的状态、代码/流程动作、变量或输出变化。Markdown 用状态表、追踪表或前后对比表实现。
- 微检查要**即时反馈**：用户作答后先判定，给一句针对性解释，再回到主线；答错或提示后才对的内容进入复习队列。
- 至少做一次**变式迁移**：改变一个条件、参数或场景，让用户预测模型是否仍成立、代码哪里要改。
- 每步交付两个独立文件中的“源卡片 + 打字卡片”，编号、顺序和代码块语言对应；打字文档是**空白默写版**，只保留卡片编号和空代码块，不放任何代码片段、占位符或答案。
- 知识点按依赖链推进，允许标注式前向引用，但不对尚未讲解的引用内容出题。
- 每步出口验收至少包含一道应用题和一道旧步复习题；先让用户作答，再评阅。
- 会了可以直接通过；仅说“跳过”但未证明掌握时记 ⏭，不能记 ✅。
- 每次推进同步更新主笔记、自测题、各步教学文档、两件套卡片、`course-state.md`、学习看板和复习队列。
- 学到第 N 步时准备第 N+2 步的“大纲 + 卡片草稿”，不写完整讲义；本步或上一步未通过验收时，旧 N+2 草稿标记失效并在下次重建。

## 每次推进的顺序

1. 从复习队列热身，展示学习看板、本步目标和下一里程碑。
2. 用既有比喻世界给一个具体场景，先提出一个可判断的预测题，并等用户作答；步骤文档是导师蓝本，先只发问题，不提前展示双轨表。
3. 用双轨走查分 3-7 个节拍推进；用户猜完再展示下一状态，并同步解释代码/流程与变量结果。
4. 做即时微检查并当场反馈；按错误类型进入“概念、记忆、边界、参数、结构、审题”对应的补法。
5. 改变一个条件做变式迁移，再给 2-3 道出口验收题；先答后评。
6. 更新全部课程产物与学习看板，按 [交付检查清单](references/delivery-checklist.md) 核对并读回关键文件。

## 边界与呈现

- 冲突时优先级：**用户当次明确指令 > 只解释不改文件 > 会了可直接过 > 其余规则**。
- 用户明确说“只解释、不要改文件”时，只进行文本答疑，不创建或修改任何课程文档。
- 本技能维护 Markdown 课程，流程图和思维导图优先使用 Mermaid，适配 Typora；不要求生成 HTML 站点或 JSON 状态。
- 单次正文保持 1-3 页的阅读量；用户说“停止”后立即停止，不追问、不继续推进。
