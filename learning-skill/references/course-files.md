## 五、文档管理与进度维护

### 5.1 文档清单

| 文档 | 用途 |
|---|---|
| 主笔记 | 课程正文浓缩 + 进度表 + 贯穿全程、逐步扩展的累进比喻地图 + 学习看板 |
| 自测题 | 每步作业/自测，含检查单；题目在前，判定要点与验收结果分开记录 |
| 各步教学文档 | 每步讲授蓝本，含主动学习节拍（先预测、双轨走查、即时反馈、变式迁移） |
| 记忆卡片·源文档 | 全部卡片代码原文汇总（独立文件） |
| 记忆卡片·打字文档 | 全部卡片的空白默写版（独立文件，与源文档编号、顺序和代码块语言对应，不含任何代码片段） |
| `course-state.md` | 跨会话状态：当前步、已完成步、已备 N+2、各文档路径、学习看板、复习队列、薄弱点 |

### 5.2 单步教学文档的主动学习结构

每步教学文档不再只是“解释 + 题目”，而应能被人独立照做。建议结构：

```markdown
# 第 N 步：<主题>

## 目标
## 核心概念（先给结论）
## 生活类比（加入累进比喻地图）
## 主动走查
### 先预测：<一个可判断的小问题>
| 节拍 | 比喻状态 | 代码/流程 | 变量或输出 | 用户任务 |
|---|---|---|---|---|
| 1 | | | | 预测… |
### 即时反馈
- 若答对：<一句话指出对在哪>
- 若答错：<指出错在哪个关系，归入哪一类错误>
## 变式迁移
改变 <条件/参数> 后，预测 <结果/边界>。
## 常见错误
## 小练习与出口验收
## 总结
```

要求：

- “先预测”必须先提出问题再给答案，答案不能和问题写在同一眼可见的位置；
- 双轨表每行只描述一个可观察状态，节拍通常 3-7 个；
- 每个核心概念都要能在表中找到对应的状态变化，不能只讲概念不落到状态；
- 变式迁移至少改变一个条件，并给出需要修改的位置或会先失效的边界。

步骤文档是导师蓝本，不是让用户一口气读完的讲义。实际授课时先只发“先预测”问题，等用户作答后再展示对应节拍和反馈；文档中的答案位置靠后，不代表课堂上可以提前披露。

### 5.3 学习看板

主笔记中维护一段“学习看板”，开讲前展示、推进后更新：

```markdown
## 学习看板
- 课程推进：3 / 8 步
- 验收掌握度：2.5 / 8（✅=1，🟡=0.5，🔴/⏭/未学=0）
- 待复习：2 项
- 当前步：第 4 步 · 队列背压
- 下一步建议：先补“边界条件”，再做第 4 步变式
- 下一里程碑：第 4 步达到 ✅
```

- 数字必须能由验收记录、进度表和复习队列算出；信息不足时标“总数待确认”，不写估计值；
- 课程推进按“已验收或已跳过的步骤数 / 总步骤数”计算；掌握度按 ✅=1、🟡=0.5、🔴/⏭/未学=0 计算；
- `course-state.md` 中同步保存同一份看板摘要，便于跨会话恢复；
- 看板用于决策（先补哪里、下一步做什么），不是装饰，因此“下一步建议”要具体到薄弱点或到期复习项。

### 5.4 `course-state.md` 最小模板

```markdown
# 课程状态

- 课程：
- 当前步：
- 已完成步：
- 已备 N+2：
- 文档路径：
  - 主笔记：
  - 自测题：
  - 卡片-源文档：
  - 卡片-打字文档：
  - 各步教学文档目录：
  - N+2 草稿：

## 学习看板
- 课程推进：
- 验收掌握度：
- 待复习：
- 当前步：
- 下一步建议：
- 下一里程碑：

## 验收记录
| 日期 | 步 | 概念 | 结果 | 提示层级 | 错误类型 |
|---|---|---|---|---|---|

## 复习队列
| 概念 | 来源步 | 到期 | 连续正确 |
|---|---|---|---|

```

### 5.5 每次推进后必做

1. 刷新主笔记进度表与学习看板（已学步 ✅ / 待学步，以及推进、掌握度、待复习、下一步建议）；
2. 追加本步浓缩正文（含主动走查摘要与作业检查单）；
3. 扩展并校正累进比喻地图，标出本步新增角色、路线或关口；旧关系若被重构，记录迁移理由；
4. 追加本步记忆卡片到两个独立文件（源文档文件 + 打字文档文件，卡片编号对应；打字文件只保留编号和空代码块）；
5. 更新复习队列（新增/移出的薄弱概念）；
6. 更新 `course-state.md`（当前步、已完成步、已备 N+2、学习看板、验收记录、复习队列、薄弱点）；
7. 生成第 N+2 步**大纲 + 卡片草稿**（不写完整讲义；遵守依赖顺序；若本步未通过验收，N+2 草稿标记失效，下次重新生成）。

### 5.6 文件位置

- 沿用用户既有的目录与命名习惯，或按用户实际提供的路径；
- **不从记忆硬猜**；找不到先问；
- 开讲前先读 `course-state.md`（若存在）；若不存在，先问用户课程文档放在哪，再创建；
- 每次推进后同步刷新 `course-state.md` 与学习看板，确保跨会话可恢复状态。

### 5.7 旧状态恢复与冲突处理

1. **先读后改**：开讲或改文件前，读取 `course-state.md` 以及其中记录的当前步、主笔记、自测题、卡片和复习队列。不要因为某个文档存在就跳过状态核对。
2. **缺失字段不猜**：旧状态缺少当前步、已完成步、掌握状态、文档路径或复习记录时，保留原文，结合现有文档与用户确认补齐；不能凭课程名称、文件编号或历史印象推断掌握度。
3. **路径失效先辨认**：记录路径不存在时，区分“课程移动”“文件改名”和“文件确实缺失”。只在用户指定的课程目录内查找候选；未确认前不要新建一套同名文件覆盖旧体系。
4. **冲突要显式核对**：状态文件、主笔记和验收记录不一致时，列出冲突项。以用户当次明确说明和可核实的课程证据为准，不用“最新修改时间”代替学习事实。
5. **保留自定义内容**：旧文件中的额外字段、备注、链接和用户自定义章节应保留；只更新本次需要变化的字段，不为套模板而重写整个状态文件。旧状态没有学习看板时，补一段摘要即可，不必推翻原有结构。
6. **未验证不等于已掌握**：从旧文档恢复时，“有教学文档”“有卡片”“当前能推进”都不能单独证明 ✅；缺少验收证据时保持未验证或向用户摸底。
7. **草稿按掌握度失效**：当前步或上一步未通过验收时，旧 N+2 草稿必须标记失效，不得继续当作已备完成项。
8. **最小修复**：能补字段就不迁移格式，能修正路径就不重建课程。确需改名或调整结构时，先保留原文件，再同步更新所有引用。
