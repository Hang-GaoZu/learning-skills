## 九、交付前检查清单（写文件前核对计划，写完后核对结果）

### 主动学习闭环

- [ ] 每个核心概念是否有用户可执行的预测、判断或补全动作，而不是只给解释？
- [ ] 是否先提出问题再揭示答案（“先答后看”），答案没有和问题挤在同一眼可见的位置？
- [ ] 双轨走查是否每行只描述一个可观察状态，并同时给出比喻状态、代码/流程与变量或输出变化？
- [ ] 用户作答后是否立即给出一句针对性反馈，并按错误类型归类？
- [ ] 是否做了至少一次变式迁移（改变一个条件/参数/场景）并指出会失效的边界或需修改的位置？
- [ ] 每个核心概念后是否都有“下一步会怎样/为什么/删掉会怎样”的微检查？

### 单步产物

- [ ] 源文档与打字文档是否两个独立文件，卡片编号对应？
- [ ] 打字文档是否为空白默写版：只保留卡片编号、标题层级和空代码块，没有 `____`、变量名、注释、要点或任何代码片段？
- [ ] 卡片是否按依赖顺序排列，前向引用术语是否未当步出题？
- [ ] 验收题是否至少 1 道应用题 + 1 道旧步复习题，且为同构变式（非原题照搬）？
- [ ] 出口验收是否优先复用本步做过的变式，而非原题照搬？
- [ ] 主笔记进度表与“学习看板”是否刷新，状态四档（✅/🟡/🔴/⏭）是否记录？
- [ ] 学习看板的推进、掌握度、待复习是否由验收记录和复习队列算出，信息不足处是否标“待确认”而非估计？
- [ ] `course-state.md` 是否更新（当前步、已完成步、已备 N+2、学习看板、验收记录、复习队列、薄弱点）？
- [ ] 累进比喻地图是否随本步扩展，新增关系是否标明，旧关系是否仍在同一世界中可解释？
- [ ] N+2 是大纲 + 卡片草稿（非完整讲义），且若本步未通过验收是否标记失效？
- [ ] 若属于轻答疑模式，是否未触发本流程、未写任何课程文档？

### 跨文件一致性验收

- [ ] `course-state.md` 中的文档路径是否真实存在；尚未创建或缺失的文件是否明确标记，而不是留下失效路径？
- [ ] 当前步、已完成步、主笔记进度表、学习看板、各步验收记录是否互相一致，“能推进”是否没有被误记为“已掌握”？
- [ ] 源文档与打字文档的卡片数量、编号、顺序和代码块语言是否一致；打字文档是否没有答案泄漏或结构提示？
- [ ] 本步自测、主笔记、教学文档和卡片是否覆盖同一范围，标注式前向引用是否没有被提前出题？
- [ ] 复习队列是否包含本步 ❌/⚠️ 概念；移出项是否确有连续两次不同场次的独立答对记录？
- [ ] N+2 文件是否同时有大纲和卡片草稿，其“有效/失效”标记是否与当前及上一步验收结果一致？
- [ ] 旧状态的自定义字段、备注和链接是否保留；本次是否只修改了课程相关文件？
- [ ] 写完文件后是否读回 `course-state.md`、主笔记进度和本步卡片的关键部分，确认实际保存结果与计划一致？
