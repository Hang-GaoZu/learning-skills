`project-state.md` 是本技能的**跨会话记忆**。没有它，用户第二天说"接着做第 3 步"，导师就只能从对话残影里猜——猜错一次，整个进度就歪了。

## 二、何时更新

- **建档**：第 0 步环境自检通过后立刻建，把语言版本、构建与启动命令、备份方式与位置、编码坑、**两个能力选项的开关**写进去。
- **每次推进后**：更新当前里程碑、已完成、验收记录、复习队列、看板、降级记录；验收存档后追加备份记录行（Git 哈希或快照目录）；修完 bug 追加调试记录。
- **模块开关变动时**：当场改"能力选项"表并写明缘由，不静默切换。
- **降级时**：当场记，写清原因与新旧方案。

## 三、续学恢复规则

1. **先读后改**：开工前读 `project-state.md` 及其记录的项目笔记、当前里程碑页、卡片与复习队列。不因为"文档存在"就跳过状态核对。
2. **缺失字段不猜**：旧状态缺当前里程碑、掌握度或文档路径时，保留原文，结合现有文档与用户确认补齐；不能凭项目名、文件编号或历史印象推断掌握度。
3. **路径失效先辨认**：记录路径不存在时，区分"项目搬走了""文件改名了"和"文件真丢了"。只在用户指定的项目目录内找候选；未确认前不要新建一套同名文件覆盖旧体系。
4. **冲突显式核对**：状态文件、项目笔记、验收记录三者不一致时，**列出冲突项交用户确认**。以用户当次明确说明和可核实证据为准，不用"最新修改时间"替代事实。
5. **保留自定义内容**：旧文件里的额外字段、备注、链接、用户自写章节都保留；只改本次需要变的字段，不为套模板重写整篇。
6. **未验证不等于已掌握**：有教学文档、有卡片、当前能推进，都不能单独证明 ✅；缺验收证据就保持"未验证"或向用户摸底。
7. **草稿按掌握度失效**：当前步或上一步未通过验收时，旧 N+2 草稿标失效，不得当"已备"计入。
8. **最小修复**：能补字段就不迁格式，能修路径就不重建项目。确需改名或调整结构时，先留原文件，再同步更新所有引用。
9. **能力选项以文件为准**：续学先读"能力选项"表——Git 关着就别催他提交、注释模块关着就别布置注释作业；旧状态没有这一栏时，开讲前补问一句并写进去，不按"默认都开"想当然。

## 四、换项目怎么办

- 同一目录换新项目 → 新建 `project-state.md`，旧的归档为 `project-state-<项目名>-归档.md`，不覆盖。
- 用户同时推进两个项目 → **一项目一目录一状态文件**，不混写；开工前先问做的是哪一个。
