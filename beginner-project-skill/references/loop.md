# 迭代反馈循环

这是 `beginner-project-skill` 的核心节拍。每个里程碑都按下面的顺序推进，**一次只推进一个可观察变化**。

完整的项目详例（贪吃蛇五步拆分与三层结构）见 [里程碑拆分](milestones.md)；本文件只给规则、定位工具和最小示例，不重复整例。

## 一、循环节拍（每步）

### 1. 拆小步（动工前）
把本里程碑再切成用户能"一口吃掉"的最小可运行单元。每个单元运行后必须**有可见输出**。

### 2. 先预测
问用户一个可判断的问题，"如果……那么……"句式，一次只问一个变量。**等用户回答**，不提前给答案。

### 3. 用户写代码
用户写这一小段。AI 的作用只有三件：解释某一行、出预测题、审查用户写好的逻辑。**不代写主体逻辑**；卡住时只给"最小提示"（一个引导问题）。

### 4. 再运行
按第 0 步定下的运行方式执行，观察实际结果。输出要能看到——终端回显、浏览器页面、文件内容都算。

### 5. 对比观察
先让用户说"和你的预测哪里不一样"，AI 再定位。**不要替用户先说出差异**，那是把他的判断机会拿走了。

### 6. 判断与定位（承上启下，见第二节）
用四象限判断这是"概念没通"还是"实现写岔"，再定位到具体层。

### 7. 即时反馈
一句话说完，格式固定：**判定 + 哪一层 + 为什么 + 下一步一个问题**。例："方向反了，在输入层——你的键位映射把上和下接反了。下一步：把映射表第一行读给我听。"

### 8. 变式迁移
改变一个条件，让用户预测影响。见第五节。

### 9. 出口验收（每里程碑末尾）
至少一道迁移题 + 一道旧里程碑复习题；**用户先作答，AI 再评阅**。

## 二、四象限分流（先算清是哪笔账）

预测与实现对错组合不同，补法完全不同。**不要用治感冒的方子治跌打。**

| 预测 | 实现 | 判断 | 处理 |
|---|---|---|---|
| 对 | 对 | 真掌握 | 通过，进入变式迁移 |
| 对 | 错 | 实现层偏差 | 定位到某一层（输入 / 状态 / 逻辑 / 渲染），给最小提示诱导他自己找 |
| 错 | 对 | 歪打正着：概念没通，代码却碰对了 | **代码对不代表懂**。回讲概念，重出同构预测题，答对才前进 |
| 错 | 错 | 概念与实现双缺 | **先修概念，再修实现**——一次只动一处，否则改完也不知道是哪处生效 |

"歪打正着"是最容易被漏掉的一格：用户代码对了，导师顺手放行，概念缺口就埋进下一步了。

## 三、定位表（问题在哪一层）

| 现象 | 可能层 |
|---|---|
| 按键没反应 / 方向不对 / 命令没生效 | 输入层 |
| 状态变了但屏幕没变 / 数量不对 / 该长的没长 | 状态层 或 渲染层（用"只打印状态、不画界面"来分辨） |
| 规则不对：撞墙没停、食物没随机、越界没判断 | 逻辑层（状态更新规则） |
| 画面错位、闪烁、字符乱、排版塌 | 渲染层 |
| 程序崩溃 / 数组越界 / 卡死 | 状态层（数据边界） |
| 一运行就报"找不到命令/模块/文件" | 环境层（先回第 0 步，不算逻辑错误） |

分辨状态层与渲染层的最省事办法：**先把状态直接打印出来看**。状态对而画面不对，就是渲染层；状态本身就错，是逻辑层。

问用户一句："你判断这属于哪一层？为什么？" 然后给一句针对性解释，再回到主线。

## 四、错误类型与补法

| 错误类型 | 表现 | 补法 |
|---|---|---|
| 环境 | 命令找不到、模块缺失、编码乱码、路径不对 | 回第 0 步重跑最小程序；把坑写进 `project-state.md` |
| 概念 | 不懂"状态 / 逻辑 / 渲染"是什么 | 用生活类比重讲，再让用户复述 |
| 边界 | 越界、撞墙没判断、空清单没处理 | 专门出"极限值"题（0、最大值、恰好相等、空集合） |
| 参数 | 方向 / 速度 / 数量传错 | 画参数传递图，追踪一个值从输入到使用 |
| 结构 | 逻辑和渲染写在一起 | 引导拆函数，先只改状态再画 |
| 审题 | 误解需求（以为要穿墙、以为要暂停） | 让用户重述需求，对照代码 |

## 五、变式迁移

改一个条件，让用户预测影响。规则：**只改一个条件**，且要求他指出"哪一层的哪一处会变"。

最小示例（待办清单）：

- "如果 `done` 后面跟的编号超过清单长度，状态层会怎样？"
- "如果清单为空时删除，程序会打印什么？"
- "如果把内存存储换成本地文件，哪一层新增代码、哪一层完全不动？"

## 六、停滞阈值与降级

- 同一里程碑**连续 3 次**修正仍未跑通 → 判定停滞。
- 降级三选一，按代价从小到大：缩小里程碑范围 → 换更简单的实现方式 → 换更熟悉的语言。
- 降级前说明原因，并写进 `project-state.md`（记降级日期、原因、新方案），下次续学不再重犯。
- 用户明确说"别教了，直接给我代码" → 立即切成品模式，退出本流程，不再出预测题、不再要求预测。

## 七、预测题模板

按层出题，一次只问一个变量：

- **输入层**：按下某个键 / 输入某条命令，程序接收到的值是什么？
- **状态层**：`items = [a, b]`，执行某操作后 `items` 变成什么？长度是多少？
- **逻辑层**：满足某条件时，哪条规则先触发？两条规则冲突时谁优先？
- **渲染层**：遍历到某个坐标时，屏幕该打印什么字符？
- **边界**：取值为 0 / 最大值 / 恰好相等 / 空集合时，下一步会发生什么？
